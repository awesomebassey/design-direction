# Contributing

`design-direction` is meant to grow as a living design library for developers, designers, and vibecoders.

Contributions should make agents better at real interface work. Keep additions practical, sourced, and easy to apply.

## Good Contributions

- New reference source with a clear use case
- Correction to an outdated source
- Component library notes with framework, license, and caveats
- Design heuristic that prevents a repeated agent mistake
- Mobile or accessibility edge case
- Motion principle with concrete implementation guidance
- QA checklist item backed by a real failure mode

## What To Avoid

- Copying paid prompts or private materials
- Reposting full articles, courses, or proprietary docs
- Adding broad inspiration without saying when to use it
- Adding generic advice that any model already knows
- Turning one personal preference into a universal rule
- Adding links that are mostly ads, lead magnets, or unavailable without context

## Reference Entry Format

When adding a source, include:

```md
### Source Name

- URL:
- Category:
- Best for:
- Agent guidance:
- License/access notes:
- Added by:
- Date checked:
```

## Review Standard

A contribution should answer:

- Does this help an agent make a better design decision?
- Is it clear when to use it?
- Is it safe to publish?
- Does it avoid copying third-party content?
- Is it placed in the smallest relevant reference file?

## Suggested Workflow

1. Open an issue using the reference or correction template.
2. Discuss whether the source belongs in the skill.
3. Submit a focused pull request.
4. Keep the canonical `skill.md` stable unless the contribution changes core behavior.
5. Add details to `references/` rather than bloating the main skill.
